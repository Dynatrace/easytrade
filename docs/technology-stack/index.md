# Technology stack

> **Audience:** Engineers building, testing, or upgrading an EasyTrade service.

EasyTrade is deliberately polyglot. Four language stacks are represented so that a
single deployment exercises Dynatrace's Java, .NET, Go, and Node.js instrumentation at
the same time, plus nginx and a SQL database. Nothing here is chosen for engineering
convenience — the variety *is* the feature.

## The four stacks

| Stack | Version | Services |
|---|---|---|
| **Go** | 1.26 | `background-service`, `db-adapter`, `feature-flag-service`, `pricing-service`, `user-service` |
| **TypeScript / Node.js** | ES modules, TS 5 | `frontend`, `loadgen`, `offerservice` |
| **C# / .NET** | net8.0 | `broker-service` |
| **Java** | 21, Spring Boot 4.0.7 | `credit-card-order-service` |
| *Config only* | — | `frontendreverseproxy` (nginx), `db` (MSSQL or Postgres) |

## Go

Five services, each its own module under `src/<service>/`.

| Concern | Choice |
|---|---|
| HTTP framework | Gin (`pricing-service`, `user-service`, `feature-flag-service`) |
| gRPC | `google.golang.org/grpc` + `protoc-gen-go` |
| ORM | GORM — **only** in `db-adapter`, with the `sqlserver` and `postgres` drivers |
| Logging | `go.uber.org/zap` (`logrus` in `db-adapter`) |
| Kubernetes | `k8s.io/client-go`, in `background-service`'s operator subsystem only |

```bash
# from the service directory
go build .
go test ./...
go test ./path/to/pkg -run TestName
```

Generated gRPC stubs are **not** committed for every service. `pricing-service`,
`user-service`, `db-adapter`, and `offerservice` each ship a `generate-proto.sh` that
regenerates them from `src/proto/`; the Dockerfiles run it at build time. Run them all
with `make generate-proto`, or one with `make generate-proto service=db-adapter`.

**Vulnerability fixes in Go** need three coordinated edits: bump the `go` directive in
`go.mod`, bump the builder image tag *and digest* in the service's `Dockerfile`, then
run `go mod tidy`.

## TypeScript / Node.js

| Service | Runtime shape | Build | Test |
|---|---|---|---|
| `frontend` | React 18 + Vite 6, React Router 7, TanStack Query 5, `lightweight-charts` | `npm run build` (vite) | `npm test` (vitest + Testing Library + jsdom) |
| `offerservice` | Express 5, `@grpc/grpc-js`, OpenFeature, Winston | `npm run build` (generates protos, then `tsc`) | — |
| `loadgen` | Puppeteer-driven browser sessions via `@demoability/loadgen-core` | `npm run build` (`tsc`) | — |

```bash
npm install
npm run build
npm run lint
```

House rules (`.claude/rules/typescript.md`): named exports only, no `any` without an
explicit justification comment, no `var`, check `response.ok` before parsing JSON, and
pin transitive dependencies with `overrides` in `package.json` — never `resolutions`.

## C# / .NET — `broker-service`

The core trading engine, and the only service with a test project. The former
standalone `engine` service was merged into it.

| Concern | Choice |
|---|---|
| Framework | ASP.NET Core, `net8.0` |
| Persistence | **gRPC to `db-adapter`** (`Grpc.Net.Client` 2.80, `Google.Protobuf` 3.35) — no ORM, no direct DB connection |
| Feature flags | `OpenFeature` 2.7 with a custom provider polling `feature-flag-service` |
| Startup | `HostInitActions` for async initialisation |
| Tests | xUnit, with hand-written fakes under `test/Fakes/` |

```bash
# from src/broker-service/
dotnet build
dotnet test
dotnet test --filter "FullyQualifiedName~SomeTest"
```

The directory was flattened in [#218](https://github.com/Dynatrace/easytrade/pull/218):
the solution now sits directly at `src/broker-service/` with `src/` and `test/`
beneath it.

## Java — `credit-card-order-service`

Spring Boot 4.0.7 on Java 21, built with Gradle.

```bash
./gradlew build          # compile + test
./gradlew test
./gradlew test --tests "com.dynatrace.easytrade.SomeTest"
```

It talks to `db-adapter` over gRPC using stubs generated by the
`com.google.protobuf` Gradle plugin at build time. The gRPC channel is initialised
lazily ([#220](https://github.com/Dynatrace/easytrade/pull/220)) so the service starts
without waiting for `db-adapter` to be reachable.

Transitive dependency bumps go in the marked block in `build.gradle`:

```groovy
// -- not direct dependencies but need bumps to patch vulns
// -- can be removed once the parent packages upgrade
```

## Cross-cutting conventions

**Health endpoints.** Services expose `/livez` (liveness) and `/readyz` (readiness) on
port 8080. Readiness is meaningful where it can be — `db-adapter`'s `/readyz` pings the
database; `broker-service` has a `DbAdapterHealthCheck`.

**Feature flags.** Every service that participates in a problem pattern reads it
through an OpenFeature client pointed at `feature-flag-service`, regardless of language.
See [Problem patterns](../problem-patterns/index.md).

**Ports.** Every service listens on `8080` internally (`db-adapter` also serves gRPC on
`50051`); `compose.dev.yaml` maps each to a distinct host port.

**Testing rules** (`.claude/rules/tests.md`): never mock the database when a real one is
available, never write an assertion-free test, never `sleep` to wait for async
behaviour. Name tests `[function]_[scenario]_[expectedResult]`.

## Vulnerability fixes

Apply a fix across **all** affected services in a single pass. Partial updates leave the
repository inconsistent, and because the Java services share a `build.gradle` structure,
a bump applied to one must be applied to every other affected one.
